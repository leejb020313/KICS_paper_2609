## 1. 한 장 요약

**무엇을 했나.** 팩트체크가 필요한 문장을 골라내는 작업에서, 가벼운 분류기(임베딩 SVM)가 모든 문장을 먼저 판정하고 **확신하지 못하는 절반에만** 대형 언어 모델(LLM)을 호출합니다. 호출한 문장은 LLM의 답으로 바꾸지 않고, **두 모델의 점수를 결합**해 최종 판정합니다.

**핵심 결과** (Claude Sonnet 5, 테스트 정확도, 5회 반복 평균)

| | LLM을 모든 문장에 호출 | 제안 방법 (절반만 호출) |
|---|---|---|
| 정확도 (CLEF / ClaimBuster) | 0.915 / 0.835 | **0.923 / 0.846** |
| LLM 비용 (1,000문장당) | \$0.168 | **\$0.084** (−50%) |
| 처리 시간 (1,000문장당) | 107초 | **60초** (−44%) |

**한 줄 메시지.** LLM 호출을 절반으로 줄여도 정확도는 떨어지지 않습니다. 5회 반복 모두에서 "0.6%p 넘게 낮지 않다"를 통계적으로 확인했습니다. 같은 조건에서 LLM 답으로 교체하는 기존 방식은 ClaimBuster에서 이를 보장하지 못했습니다.

## 3. 핵심 주장과 근거

**주장.** 제안 방법은 LLM 호출을 절반으로 줄여도 전량 호출과 같은 수준의 정확도를 유지합니다.

**근거.** 제안 방법과 전량 호출의 정확도 차이에 대해, 테스트 문장을 2,000번 다시 뽑는 부트스트랩으로 95% 신뢰구간을 구했습니다. 아래 표는 5회 반복 중 **가장 나빴던 회차의 신뢰구간 하한**입니다. 이 값이 −0.6%p보다 위에 있다는 것은 "제안 방법이 전량 호출보다 0.6%p 넘게 나쁘지 않다"는 뜻입니다.

| 호출률 50% | CLEF | ClaimBuster |
|---|---|---|
| **제안 방법 (결합)** | **−0.35%p** | **−0.58%p** |
| 기존 방법 (교체) | −0.59%p | −2.26%p |

- 제안 방법은 두 데이터셋 모두에서 기준을 만족합니다. 평균으로는 오히려 0.8%p, 1.1%p 높습니다.
- 기존 방법(교체)은 ClaimBuster에서 하한이 −2.3%p까지 내려가 이를 보장하지 못합니다. 따라서 이 보장은 "절반만 호출하는 구조"가 아니라 **"결합"** 덕분입니다.
- 두 번째 LLM(Haiku 4.5)에서도 구도가 같습니다. 제안 방법의 하한은 −1.6%p 이상이었고, 교체 방식은 CLEF에서 −3.1%p까지 내려갔습니다.

**주의.** 0.6%p는 미리 정한 기준이 아니라, 관측된 가장 나쁜 하한(−0.58%p)을 올림한 값입니다. 그래서 원고에는 "δ 안에서 비열등하다"가 아니라 "0.6%p 넘게 낮지 않음을 확인했다"는 사실로만 적었습니다.

## 4. 설계 선택: 왜 이렇게 했는가

### 4.1 왜 LLM을 전부 쓰지 않고 캐스케이드인가

- 실제 팩트체크 서비스 운영사가 "모든 문장에 대형 LLM을 쓰는 것은 운영 규모에서 감당하기 어렵다"고 보고했습니다 [1].
- 같은 연구진이 "가벼운 모델이 확신하지 못할 때만 LLM에 넘기는 방식"을 향후 과제로 제시했습니다 [2].
- 이 논문은 그 과제를 구현하고 평가한 것입니다.

### 4.2 왜 첫 단계가 임베딩 SVM인가

**결론: 더 정확한 대안은 있지만, 비용과 시간을 줄이는 이 논문의 목적에는 지금 선택이 맞습니다.**

| 첫 단계 분류기 | 제안 방법(50%) 정확도 | 문장당 CPU 시간 |
|---|---|---|
| **임베딩 SVM (논문)** | 0.920 / 0.847 | **6.6 ms** |
| 같은 임베딩 + 로지스틱 회귀 | 0.919 / 0.848 | 비슷 |
| 임베딩 SVM, 하이퍼파라미터 튜닝 | 0.921 / 0.845 | 비슷 |
| 더 큰 임베딩(mpnet) + SVM | 0.925 / 0.856 | 43 ms |

※ 이 표는 별도 비교 실험의 결과라, 표본 추출 방식 차이로 논문 수치(0.923 / 0.846)와 조금 다릅니다. 모든 행을 같은 방식으로 비교했습니다.

- 더 큰 임베딩은 0.5~0.9%p 더 정확하지만 첫 단계가 6.5배 느려집니다. 그러면 시간 절감이 44%에서 약 10%로 줄어듭니다(추정).
- 지금 임베딩은 비교 대상인 NN-PPI가 쓰는 것과 **같은 것**입니다. 그래서 "같은 정보로 NN-PPI보다 같거나 낫다"는 비교가 공정합니다 (SVM 0.859 / 0.790 대 NN-PPI 0.834 / 0.785).
- 파인튜닝한 인코더(RoBERTa 등)는 GPU가 필요해 시험하지 않았습니다.

### 4.3 왜 LLM 답으로 교체하지 않고 결합하는가

**결론: LLM이 "사실 확인이 필요하다"고 보는 기준이 데이터셋의 정답 기준과 달라서입니다.**

- LLM 점수를 그대로 쓰면 정밀도는 0.98 / 0.91로 높지만 재현율은 0.61 / 0.42에 그칩니다. LLM이 정답보다 훨씬 보수적으로 판정한다는 뜻입니다.
- 결합 공식은 분류기가 "불필요" 쪽으로 강하게 기울수록 LLM에 더 높은 기준을 요구합니다. 교체 방식은 항상 같은 기준을 씁니다.
- **실제 사례**: 한 공약 문장(정답: 불필요)의 LLM 점수는 0.35였습니다. 고정 기준 0.16을 쓰는 교체 방식은 "필요"로 틀렸지만, 제안 방법은 분류기 판단 때문에 기준이 0.41로 올라가 맞혔습니다.
- 같은 문장을 호출할 때 결합 방식은 모든 호출률에서 교체 방식보다 평균 정확도가 높았습니다.

### 4.4 왜 이 결합 공식(로지스틱 회귀)인가

**결론: 시험한 대안 중 가장 좋거나 공동 1위이고, "가중치를 학습한다"는 점이 핵심입니다.**

| 결합 방식 | 제안 방법(50%) 정확도 |
|---|---|
| **로지스틱 회귀 (논문 식 1)** | **0.920 / 0.847** |
| 상호작용항 추가 | 0.920 / 0.848 |
| LLM 점수에 로그 변환 | 0.917 / 0.840 |
| 그래디언트 부스팅 | 0.916 / 0.843 |
| 학습 없이 단순 평균 | 0.915 / 0.836 |

- 더 복잡한 모델은 나아지지 않았습니다. 학습 데이터가 1~2천 문장이라 계수 3개짜리 모델이 안정적입니다.
- **학습 없이 평균하면 확실히 떨어집니다** (−0.5 / −1.1%p). 라벨로 결합 가중치를 학습해야 LLM과 정답 기준의 차이를 보정할 수 있다는 직접 근거이며, 최신 관련 연구 [8]과 구별되는 지점입니다.
- 결합 모델을 "실제로 호출되는 절반"으로만 학습해 봐도 나아지지 않았습니다 (0.9195 / 0.8463).

### 4.5 왜 호출률 50%인가

- 테스트를 보지 않고 학습 데이터만으로 정했습니다. 50% 이후로는 더 호출해도 정확도가 CLEF 0.06%p, ClaimBuster 0.11%p만 올랐습니다.
- 평균 정확도만 보면 제안 방법은 CLEF 30%, ClaimBuster 40%에서 이미 전량 호출 수준에 도달합니다. 다만 30~40%에서는 3절의 "0.6%p 보장"이 성립하지 않아, 원고에는 "평균 도달"로만 적었습니다.
- **주의**: "증가 0.1%p 이하"를 엄격한 규칙으로 쓰면 ClaimBuster는 60%가 됩니다. 그래서 원고에는 규칙처럼 쓰지 않고 실제 증가값을 그대로 적었습니다.

### 4.6 LLM, 데이터, 비교군 선택

| 선택 | 이유 |
|---|---|
| LLM: Claude Sonnet 5 | 선행 연구의 가장 강한 설정이 "상용 LLM + NN-PPI"라 같은 급으로 비교. 2차 확인은 Haiku 4.5 |
| 40문장씩 묶어 LLM 채점 | 호출 수 절감. 1문장씩 채점한 결과와 품질 차이 없음 (AUC 0.991 대 0.990) |
| 프롬프트: NN-PPI의 판정 기준 | 비교 대상과 같은 기준이어야 차이가 방법에서 나온다고 말할 수 있음 |
| 데이터: CLEF 2024, ClaimBuster | NN-PPI가 쓴 데이터라 원 논문 수치와 직접 비교 가능 |
| NN-PPI 재현 (Gemma 3 4B) | 원 논문 설정 그대로. 가중 F1 0.835 / 0.785 (원 논문 0.827 / 0.760) |
| 비교군: 교체 방식 (같은 호출률) | 같은 문장을 호출하므로 차이가 "판정 방식"에서만 생김 |
| 비교군: 전량 호출은 두 설정 중 강한 쪽 | 약한 쪽과 비교해 유리하게 보이지 않도록 |

### 4.7 평가 방법

| 선택 | 이유 |
|---|---|
| 지표: 정확도 | 문장별로 맞음/틀림이 정해져 짝지은 검정이 가능. 가중 F1로 바꿔도 제안 방법이 가장 높음 |
| 학습 데이터 80%로 5회 반복 | 특정 학습 데이터에 우연히 맞춘 결과가 아님을 확인 |

| 비용: 실측 토큰 × 정가 | 테스트 배치 23개를 다시 호출해 측정. 도구가 덧붙이는 프롬프트는 제외 |

## 6. 결정이 필요한 것

**1. ClaimBuster 양성 F1 결과를 원고에 밝힐지**
- 공식 지표(양성 F1)로 보면 ClaimBuster에서는 전량 호출(임계값 조정)이 0.729로, 제안 방법 0.716보다 높습니다. CLEF에서는 제안 방법이 0.861로 가장 높습니다.
- 넣으면 원고에서 한 줄이 늘어나 다른 문장을 줄여야 합니다.

**2. "학습 없이 평균하면 떨어진다" 결과를 원고에 넣을지**
- 결합 가중치를 학습하는 이유의 직접 근거입니다(4.4절).
- 넣으려면 유의성 검정을 추가하고 한 줄을 줄여야 합니다.

**3. JEV 버전 원고를 따로 투고할지**
- 상용 판정 모델 JEV를 첫 단계로 쓴 원고(`jev-paper` 브랜치)도 2쪽으로 완성되어 있습니다.
- 데이터와 결합 방법이 겹쳐 중복 투고로 보일 수 있습니다.
